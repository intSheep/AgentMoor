# 模型调用前的持久预算

[INT-76](https://linear.app/intsheep/issue/INT-76) 提供可信网关调用的 `ReserveSandboxModel`。每次转发前必须成功预留：一次请求、本次实际输入字节数，以及一份固定的最大响应字节数。数据库提交成功后才返回许可；上游失败、丢失应答或重启都不退款。它限制访问量，不是模型费用或准确 token 计费。

第一次预留固定整个受信策略：路由/模型策略摘要、请求总数、输入总量、输出预留总量、每次最大输出。后续字段变化会冲突；取消、过期、完成、错误 attempt/用途、撤销或结果已封存时不再授权。各 run 独立记账，收集后的执行身份也不能重新分配额度。

| 硬上限 | 值 |
| --- | --- |
| 每 run 请求数 | 128 |
| 每 run 输入总量 | 16 MiB |
| 每 run 输出预留总量 | 64 MiB |
| 每请求输入 | 256 KiB |
| 每请求输出预留 | 4 MiB |

部署策略可以调低这些值。先检查剩余额度再相加，损坏或越界的持久计数也会拒绝。并发预留和状态变化沿用 Catalog 的互斥及独占写租约；读取走连接池。SQL 可能等待，因此提交前再次检查当前模型能力及原始截止时间。

## 实际验证与限制

源码 `99d1821dbe82cc5db032dd1a313087f53ffbe9e2` 的 fmt/check/demo、SQLite race、平台 race/vet 及真实 `make test-services` 均通过。[结构化证据](evidence/sandbox-model-budget-2026-11-27.json)

同一契约在 SQLite 和一次性 PostgreSQL/S3 上运行：48 个并发调用在额度 7 下恰有 7 个成功；所有策略字段漂移、精确上限和多一个字节、损坏计数、过期/撤销/完成/封存输出、旧 attempt 均有正反例。丢弃已成功返回值后重开 Catalog，额度仍已消耗。实际终止 PostgreSQL 独占租约连接后，新账本与已有账本都不成功预留，原计数不变。测试服务与卷已清理。

本组件未转发模型请求，不管理 HTTP 连接、token 上限或并发流。后续网关还必须绑定受信上游/模型，限定请求与响应大小和输出 token，在原截止时间或权限撤销时中断活动请求，并拒绝共享上游身份下的跨租户对象引用。网关重试一次转发须再扣一次额度；丢失额度比重复使用额度更安全。

生产网关、真实 Codex TLS 兼容、网络/资源及 SaaS 隔离执行仍由 [INT-71](https://linear.app/intsheep/issue/INT-71) 继续验收，不可信任务入口未开放。
