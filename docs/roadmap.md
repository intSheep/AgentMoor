# AgentMoor 路线图

文档版本：0.1 · 状态：提案。本文的 V1 / V2 是验收阶段，不是发行版本或 API 版本。

**要解决的问题：** SaaS 能不能用同一套接口把任务交给原生 Agent，在计算实例销毁后，仍然可靠地取回交付物、继续同一段工作？当前优先把 **Codex 完整跑通**，再扩大支持范围。

## 从哪里开始

- **现在可跑：** 检出 [`v0.1.0-alpha.1`](https://github.com/intSheep/AgentMoor/releases/tag/v0.1.0-alpha.1)，按 [README](../README.md#quick-start) 安装依赖，执行 `make demo`，看见四条 `v1` 记录和 `Workspace restored and verified.`。这只演示本机资产保存和恢复，不执行 Agent 任务。
- **现在可验证集群契约：** 按 [任务契约](task-contract.md#一条命令复验) 安装依赖，执行 `make test-k8s AGENT=codex`。它会启动一次性 kind 集群，走 SaaS HTTP 接口，用原生 CLI 和模拟模型验证交付、追问和取消。不是文件工具工作流，也不需要真实模型账户。主机需要 Go 1.27.4、C 编译器、Make、Docker、kind、kubectl、Python 3 和 OpenSSL；首次拉镜像或安装固定 CLI 版本仍需联网。
- **下一版 Quick Start 的目标：** 在一台满足依赖的干净机器上，面向 SaaS 集成者给出两条独立路径：不需要密钥的集群验收，以及凭自己模型凭据运行的真实文件示例。每条路径有前置依赖、可复制命令、可验算输出、失败时的第一条排查命令和清理步骤；文档不要求读测试源码才能跑通。先检查依赖、Docker 是否可用、以及各阶段失败点；分别记录冷启动（含拉取）和暖启动耗时，不承诺未经实测的启动时间。输出可分享的脱敏证明：三个不同 Pod UID、原生会话 ID 的稳定替代标识及适配器类型、产物 SHA-256。预构建二进制和镜像是后续优化，不是当前依赖。

## 里程碑与退出条件

| 优先级 | 阶段 | 完成标准 |
| --- | --- | --- |
| P0 | V1a：Codex 文件工具与交付 | 同一条外部 SaaS 路径，以真实 Codex CLI 读取独立的工作区输入并运行工具，产生实际文件；平台把该文件字节发布为资产而不是把最终回答改名。可验证的脚本端点测试与真实模型运行分别记录结果。[例 1](verification-matrix.md#例-1文件到文件codex) |
| P0 | V1b：跨 Pod 继续做事 | 两次 follow-up 均在新 Pod / 空工作卷运行。第一轮基于已恢复的文件修改结果，第二轮验证已修改的版本、上下文和新输入；以不可变旧版本、工作区变化和同一原生会话 ID 为证据。只记住 CSV 或随机码不算通过。[例 2](verification-matrix.md#例-2销毁计算后继续修改已有文件) |
| P0 | V1c：失败可解释且不会丢掉上次成功 | 对活跃工具回合分别做取消和进程丢失；终态、最近成功引用及旧版本下载都被外部客户端验证。公布可重试条件和未归档内容的丢失边界。[例 3](verification-matrix.md#例-3取消失联与重试) |
| P1 | V2：持久化组合下的完整 SaaS 契约 | 用 PostgreSQL + S3 兼容存储跑同一组端到端场景。验证 Job/Worker 和控制面重启、稳定调度标识、明确的重试与失败状态；报告写出确切后端版本和注入点。单独跑通过 `make test-services` 不能关闭本项。[矩阵](verification-matrix.md#v2-退出门槛) |
| P2 | 扩适配器与文档站 | Codex 门槛跑稳后，再逐一给其他 CLI 加同一能力测试，仅公布实际通过的组合。文档站如有需要从仓库 Markdown 生成，展示版本和证据，不单独维护另一套手册。 |

**给贡献者的第一批切入点：** 先实现无模型密钥的文件工具契约与外部验算脚本；其次补齐 Quick Start 和失败排查；随后为后端组合增加可切换的集群 fixture。每个 PR 说明变更影响的适配器/后端、可重放命令、以及还没验证的组合。真实模型运行留给可控环境，不让外部贡献者因缺少密钥无法完成基本验收。

**暂不做：** 跨 CLI 原生会话迁移、实时迁移执行中的进程、取消后回滚外部副作用、通用 Agent 平台或调度器、免配置生产级多租户部署。保留当前首轮 Worker 由部署方配置的边界，除非出现明确的集成需求。功能未通过矩阵前不提升为支持承诺。
