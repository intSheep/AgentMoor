# Guest 的限权 TLS 传输

[INT-75](https://linear.app/intsheep/issue/INT-75) 增加固定沙箱进程 `guest-run`：从独立 HTTPS 网关取回本回合输入，验证完整字节后调用一次[原生 Guest 核心](native-guest.md)，再上传封存结果。它不持有平台 token、数据库/对象存储凭据或共享模型密钥。

该命令供受信 Pod 模板使用，不是 SaaS 或本机客户代码入口。控制器、网关、网络与资源验收尚在接入，`untrusted-isolated.v1` 仍拒绝执行。

## 固定的传输权限

| 操作 | 权限与限制 |
| --- | --- |
| 取输入 | `GET /input`，只带 input capability；完整输入必须等于受信 Pod 参数里的外层 SHA256 和大小，随后才可运行原生命令。 |
| 传结果 | `PUT /output`，只带 output capability；携带固定摘要和大小，成功应答为 204。重试读取同一份封存文件，不重新执行 CLI。 |
| 访问模型 | 首版只支持 Codex，通过固定 `<gateway>/v1` 和 model capability 访问；实际上游密钥留在网关之外的可信配置中。 |
| 临时身份 | 只读 DownwardAPI 目录的 `input`、`output`、`model` 文件，允许 Kubernetes 的原子更新符号链接，打开后检查普通文件及长度。FIFO 和超大文件拒绝。 |
| 网络 | 只接受固定 HTTPS origin，无路径、查询串或用户身份；独立校验证书，不继承环境代理，不跟随重定向，响应头有界。 |
| 截止时间 | 沿用原回合的绝对 deadline；下载、执行、上传和有限重试共用，重试不分配新时长。 |

输入和结果各最多 64 MiB，可由受信命令参数调低。传输只在临时私有目录内写 0600 文件，失败和正常结束都清理。HTTP 永久错误不重试；下载流中断或上传应答丢失只重试对应传输。一次失败的上传不能成为第二次原生执行的理由。

传输客户端的 `--ca-file` 为网关 HTTPS 提供信任根。**原生 Codex 的模型 HTTPS 客户端也必须信任同一网关证书**：私有 CA 应由部署方预装进固定镜像的系统信任库；这个参数不会自动修改原生 CLI 的证书配置。实际 Codex 经私有 CA 模型网关的整体验收仍待后续，不能由传输单元测试代替。

## 当前验证

测试使用真实 TLS 服务和明确命名的测试子进程；不模拟成供应商 CLI。服务完整接收第一次 PUT 后真实断开 TCP 丢弃应答，第二次收到同一 capability、摘要、大小和字节；执行回调及子进程均只有一次。还覆盖输入流中断重试、篡改/长短输入不执行、不同 CA、重定向、超大响应头、错误用途、永久错误、截止/取消、空或超限输出不上传、部分写入失败及临时文件清理。

CLI 另验证错误摘要、损坏归档、错误适配器和缺模型不会启动原生命令或上传；失败后清理执行目录并恢复进程环境，避免测试间遗留能力令牌。完整仓库 fmt/check/demo 已通过；实际源码与四 CLI 兼容性结果见[证据](evidence/guest-capability-transport-2026-11-27.json)。

这些证据不证明实际模型代理、生产 Pod 控制器、网络策略、资源耗尽、SaaS 发布或生产 HA。后续网关须用持久能力状态及预算鉴权，在取消/截止时中断活动流，并对结果完整封存；最终可信 Worker 仍须重新校验结果。
