# v0.1.0-alpha.2 · Go Adapter SDK 预览

这是首个包含公开 Go Adapter SDK 的 **0.x 预览**，不是 1.0 稳定接口。先收集独立接入反馈，再确定冻结范围和兼容维护规则。[接口与使用指南](../adapter-sdk.md) · [Linear INT-97](https://linear.app/intsheep/issue/INT-97)

## 此版本提供什么

- 根 Go 模块改为 `github.com/intSheep/AgentMoor`；仓库外模块通过 `sdk` 实现 Adapter，通过可选 `sdk/contracttest` 运行共用资产契约。
- 公开发现、Session、版本观测和可选任务接口；适配器仍由受信启动代码显式注册。没有动态加载或 Native Hook/RPC 安装协议。
- 共用契约覆盖合成文件与原生导入/导出两种机制、原始字节、固定旧版本、新路径恢复和拒绝反例。SDK 核心不引入 Worker/SQL/S3；可选 runner 会引入测试依赖。
- 同期已合并首版自主管 Linux/gVisor 的凭据、隔离、停止证明、仅运维审计及 PostgreSQL/S3 组合验收。范围与来源见[安全边界](../security-boundary.md)，不能据此声称全部 CLI 已支持不可信隔离任务。

## 从旧预览迁移

旧 `v0.1.0-alpha.1` 保持原样，不包含 SDK，根模块名为 `agentmoor`。新接入使用下列确切版本；不要以旧标签或 `@latest` 代替：

```sh
GOWORK=off GOTOOLCHAIN=local go get github.com/intSheep/AgentMoor/sdk@v0.1.0-alpha.2
```

已有源码接入者需将 `agentmoor/...` 导入改为 canonical 路径；外部模块使用公开 `sdk`，不能直接导入 `internal/...`。本地开发的 `replace` 可保留为开发方法，发布接入应检查 `go list -m -json github.com/intSheep/AgentMoor` 的版本且没有 `Replace`。

当前需要 Go `1.27.4`，面向 Linux/macOS。核心可在 `CGO_ENABLED=0` 下构建；完整资产 runner 需要 CGO、C 编译器和本地 HTTP 监听。原生 CLI 支持仍按[固定版本矩阵](../mvp.md)验收。真实模型验证按既定安排后补，本版本不增加相关结论。

## 发布与接入验收

PR 检查与审阅通过、合并到 main 后，维护者以确切提交创建新的根模块标签及 GitHub prerelease；旧标签不移动。发布后执行：

```sh
python3 scripts/check-sdk-release.py v0.1.0-alpha.2 --output /absolute/new/sdk-release-evidence
```

保留版本、模块下载校验和、标签提交、实际测试名和输出；仅本地替换或编译通过不能代替远程接入验收。当前维护者消费者与独立 agent 演练都使用合成数据，不能冒充真人第三方接入认证。后续预览的接口或行为变化将使用新标签并写明迁移步骤。
