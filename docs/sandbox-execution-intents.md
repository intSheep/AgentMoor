# 沙箱执行的持久状态

本项是 [INT-73](https://linear.app/intsheep/issue/INT-73) 的存储层，不启动 Pod，也未开放不可信任务。实际控制器、模型网关、网络及资源验收继续由 [INT-71](https://linear.app/intsheep/issue/INT-71) 承接。

## 为什么先保存执行身份

控制面可能在请求 Kubernetes 创建 Pod 后、收到应答前退出。恢复时不能因为不知道结果就再启动一次原生命令。本层以作用域、回合和原任务的私有 attempt 固定身份；输入绑定数据库里已有的 Spec、父 checkpoint、固定 Skill 和截止时间，以及部署方选择的 profile 摘要。

输入封存后，`FenceSandboxCreate` 先持久化创建围栏，再只向第一次调用返回创建许可及三种临时能力令牌。重复调用和数据库重开都不重新发许可。围栏与实际创建之间退出可能导致零次执行，不能称为“保证恰好执行一次”。Kubernetes 控制器还须实现 UID 核对、模糊创建结果查询及禁止第二次创建。

## 接口保持的边界

| 内容 | 存储层约束 |
| --- | --- |
| 输入与输出 | 各最多 64 MiB，先冻结并校验完整字节的大小和 SHA256，再封存；候选摘要在对象写入之前落库。 |
| 能力令牌 | input、output、model 分用途；每份含 256 位随机量，只保存摘要，不写入 Run 的 JSON。鉴权检查真实任务 attempt、状态、期限及撤销。 |
| 模型访问 | 这里只鉴权，没有代理或模型预算。后续网关必须在转发前持久化预留额度。 |
| 输出确认 | 上传成功仍不可发布；必须登记同一 Pod UID 的正常退出并确认删除，才允许可信 Worker 读取。 |
| 丢失应答 | 同一输出摘要和大小可重投；冲突内容拒绝。可信 Worker 在任务完成后可重读已封存结果，guest 的权限不因此恢复。 |
| 对象读取 | 返回持久化的预期摘要和大小，读流检查整个 envelope。调用方必须完整读取且检查错误，在完成校验前不能执行或发布部分内容。 |
| 回收 | 沿用公开 GC 的 24 小时窗口。活跃及保留期内的输入、输出、未封存候选保护真实对象；共享引用不能误删。回收后保留身份、创建围栏和 Pod 归属墓碑，禁止复活。 |

写入继续绑定 Catalog 的独占数据库租约连接；查询使用连接池。对象写入期间丢失租约时，最后的封存写入必须失败，候选引用保留给后续所有者处理。状态变更接口仅供可信控制器内部使用，不能直接作为 guest HTTP 路由暴露。已回收墓碑当前只支持读取归属；后续控制器需处理迟到清理确认，不能为清理重新创建执行。

## 2026-11-27 实际验证

实现源码 `b7ab6f14ce44199825c23b081468983b5d295a65` 的 `make fmt`、`make check`（含 race）和 `make demo` 通过；同一源码的 `make test-services` 在一次性 PostgreSQL/S3 上退出 0，服务和卷已清理。[结构化记录](evidence/sandbox-execution-intents-2026-11-27.json)

SQLite 与真实 PostgreSQL/S3 共用契约覆盖并发创建许可、固定父版本/Skill、取消/过期/越界/跨作用域、输出应答重投、退出/删除门禁、共享引用与真实孤儿删除、删除失败重试。服务测试另真实重开 Catalog；主动终止拥有租约的 PostgreSQL 连接，分别验证后续写入拒绝，以及 S3 已成功写入、最终封存前丢失连接时仍不封存或重新授权。

这些测试没有创建 Kubernetes Pod，没有运行原生 CLI，不证明网络隔离、资源上限或生产 HA；现有不可信执行拒绝门禁保持关闭。
